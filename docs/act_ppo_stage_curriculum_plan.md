# ACT PPO 阶段训练：起点、里程碑和截止规格

日期：2026-09-28。原六阶段设计草案。当前实施范围已按用户要求缩小为 **S0/S1**，实现与验证以 [S0/S1 训练说明](act_ppo_s0_s1_training.md) 为准；S2–S5/FULL 的新阶段接口暂不实施。

用户约束：用 PPO 继续微调已有 ACT，不引入教师示范或 BC；传统控制可以仅用于准备训练起点。最终由一个 ACT 从 HOME 自主完成抓放并回 HOME。

## 1. 阶段划分

建议六种局部训练起点，加完整流程 FULL。GRASP 与 LIFT 第一版放在同一训练段内，但分别记录 `grasp_confirmed` 和 `lift_confirmed`，避免把一瞬间双指接触当作已经学会抓取。

局部段首先采用统一完整任务目标，通过起点和采样截止集中练习不同部分。`training_stage` 与现有 `TaskPhase` 分离：前者表示本次要检查的训练段，后者表示实时物理进度。成功后可以切段结束采样，也可以在连接训练中让同一个 ACT 继续，不做控制器摆位。

| 训练段 | ACT 接管时的起点 | 成功里程碑 | 初始采样预算 |
| --- | --- | --- | --- |
| S0 HOME_HOLD | 无目标；机器人已稳定在 HOME 附近 | 观察窗结束时，六轴 HOME 误差及速度达标，最后至少连续 3 s 稳定；同时报告整窗误差和抖动 | 5 s / 150 步 |
| S1 REACH | HOME；物体稳定在源位置；相机已更新到目标出现之后 | 合格抓取前姿态 `reach_ready`，定义见下文 | 10 s / 300 步 |
| S2 GRASP_LIFT | 源物体附近的合法抓取前姿态；夹爪开口适当；尚未夹持 | 本次真实抓取后自主抬升至少 2 cm，并持续保持有效抓取 | 8 s / 240 步 |
| S3 TRANSPORT | 物体在源位置附近，真实夹持并已抬升，底面高出源支撑面约 2–4 cm | 当前仍夹持；完整物体投影在目标区内；底面高出目标支撑面 2–5 cm，低速稳定 0.2 s | 8 s / 240 步 |
| S4 PLACE_RELEASE | 与 S3 的合格终点一致：物体在目标区上方、夹持有效且低速 | 合法释放、稳定支撑、双指均无接触、夹爪撤离，形成 `placed_stable` | 8 s / 240 步 |
| S5 RETURN_HOME | 物体已稳定释放在目标区；夹爪已撤离物体，手臂尚未回 HOME | 六轴回 HOME、静止连续 3 s，期间物体保持放置有效 | 10 s / 300 步 |
| FULL | HOME，无目标；等待后目标出现 | ACT 无辅助完成 reach、抓取抬升、搬运、释放、回 HOME 并保持 | 首轮候选 60 s / 1800 步 |

以上时间按 30 Hz 标称换算，是首轮调试预算，不是已经验证的最优参数或硬件可达时间。初始化耗时不计入 ACT 预算，但另行记录。FULL 预算需要通过实测完整轨迹时间调整，不能把旧 600 步或这里的 1800 步当作必然最优。

HOME 5 s 是观察窗口，不意味着所有完整任务都在第 5 s 出现目标；连接训练应改变目标出现时刻。HOME 第一版从 HOME 附近开始练保持；从远处返回由 S5 负责。

## 2. 可计算的成功判据

### 2.1 HOME

当前配置 HOME 六轴角度约为 `[0, -98, 92, 65, 0, -5]` 度。实现必须读取 `home_joint_positions_rad`，不复制角度常量。

- 全部六轴 `abs(q - q_home) <= 1°`。
- 全部六轴 `abs(q_velocity) <= 0.03 rad/s`。
- 新鲜证据持续满足至少 3 s；第一版阶段评估固定这个保持时长，避免每集门槛变化难以比较。
- S0 运行满 5 s，不能只在起点已经符合 HOME 时马上判成功；同时报告最大误差、最大速度、稳定时间占比。中途偏离后恢复仍会体现在这些指标中。
- S5 还要求物体保持在目标区、被支撑、低速且已释放。

现有 idle 模式不会因为 HOME 达标产生完整任务 `outcome=success`，需要独立阶段评估器。

### 2.2 REACH

现有 `pregrasp_ready` 的语义：

- grasp FK 参考点到**物体中心三维距离 <= 2 cm**；
- 工具方向误差 <= 20°，同时考虑朝向物体和局部 +Z 向世界下方；
- 实测夹爪开口 `q_gripper - q_home_gripper` 在 `[0.45, 0.90] rad`；
- 尚未激活抓取、未曾抬升，目标在目标区外；
- 新鲜证据连续满足 0.15 s。

这里的 4.5 cm 是抓取候选区域，不能算 REACH 成功；`approach_reference_offset_m=0.04` 只用于方向计算，也不是“到物体上方 4 cm”的位置目标。

建议第一版新增 `reach_ready` 作为更明确的阶段边界，复用上述几何阈值，并增加候选约束：

- XY 误差 <= 1 cm，grasp 参考点高于物体中心 0–2 cm，同时仍要求三维距离 <= 2 cm；
- 物体静止，并仍在源位置允许范围内；不能推走方块后靠近它而通过；
- 初始化额外检查夹爪实际可夹持的朝向、指部与桌面间隙和关节限位余量；当前仅工具轴朝下并不能约束绕轴方向；
- 全部候选条件在同一段新鲜证据上保持 0.15 s，不能只计旧 `pregrasp_ready` 的计时。

新增 XY/高度与物理几何检查必须 live 标定后启用，不宣称当前现成代码已经覆盖。若策略直接完成了更强的真实抓取/抬升，可以记录 REACH 已经通过后续动作达成，不强迫它先张爪停够时间再抓。

### 2.3 GRASP_LIFT

使用现有严格接触认证，区分两个里程碑：

1. `grasp_valid`：左右指同时接触同一目标，接触同步有效，grasp 距离 <= 4.5 cm，相对位置漂移 <= 1.5 cm，在合法源区获得并持续至少 0.1 s。
2. `grasp_valid && attempt_lifted`：本次抓持相对抓取起始底面提高至少 2 cm，且物体底面高于源支撑面至少 2 cm，持续至少 0.1 s。

阶段最终成功使用第二项，不能仅使用锁存的 `lifted_once`，也不能用夹爪关闭命令替代接触证据。曾经抬起随后又掉落不能视为当前有效持物终点。

### 2.4 TRANSPORT

现有 `carried_into_goal` 是历史标志，需要同时检查当前状态：

- `grasp_valid && attempt_lifted && target_in_goal`；
- 完整定向物体投影包含 2 mm 边界余量后仍在目标区内；
- 物体底面高于目标支撑面 2–5 cm；
- 候选低速门槛：线速度 <= 0.05 m/s，角速度 <= 0.4 rad/s；以上条件新鲜证据持续 0.2 s。

高度上限、低速和持续时间是拟新增的交接条件，需物理验证。目标是让 PLACE 获得可执行的起点，而不是高速掠过目标区瞬间通过。若 ACT 连续完成合法放置，可以按更强的下游证据认可运输已达成，不要求重新拿起物体以满足悬停窗口。

### 2.5 PLACE_RELEASE

复用现有严格 `placed_stable` 判据，并保留实际抓持、抬升和运输历史：

- 释放时物体在目标区内，底面相对支撑面位于 `[-6 mm, +12 mm]`，线速度 <= 0.05 m/s，角速度 <= 0.4 rad/s；
- 最终完整投影在目标区内、底面支撑高度误差 <= 6 mm；
- 线速度 <= 0.015 m/s，角速度 <= 0.15 rad/s；
- 左右指都没有目标接触，grasp 参考点距物体 >= 6 cm；
- 连续稳定至少 0.4 s。

`valid_release`、物体中心在目标区、开爪命令，任何一项单独都不足以结束 PLACE。

## 3. 起点准备：位置与历史必须一致

优先在源位置 `(0.26, 0)` 附近做小范围验证，读取实际支撑高度、目标尺寸和目标区位置，不能把世界坐标写死为所有场景的规范。

S2 候选起点：`p_grasp ≈ p_object_center + (0,0,0.015 m)`，工具轴向下、绕轴方向与夹爪几何匹配，相对 HOME 的夹爪开口约 0.70 rad；物体稳定支撑，无双侧夹持。用有界控制到达并验证，而不是只发一条关节命令便默认已经到位。该几何种子仍需重复实测。

S3 候选起点：真实抓住并抬起到物体底面离源支撑面约 3 cm，尚在目标区外。S4 候选起点：真实持物搬到目标区中央上方，物体底面距目标支撑面约 3 cm，符合 S3 完成条件。S5 可用已放置、静止、无接触的场景配合 `idle_completed` 独立训练，但标记辅助起点；后期改用 ACT 真实放置终点衔接。

**不能在上述持物起点上直接调用现有普通 reset：**

- `TaskStateTracker.reset` 清除接触锚点、本次抓取、抬升、搬运及释放历史；
- 抬高后再 reset，会失去之前抬升证据，要求从新起点再次抬升；
- `pick_place` 当前禁止目标已经位于目标区内的初始化，因此 S4 直接 reset 会报错。

建议实现准备前缀：从合法场景开始，tracker 观察控制器实际形成的接触、抬升和搬运，但不将其动作加入 PPO。准备结束后保留有效 tracker 证据，重新建立奖励基准、上次命令和阶段计时，清空或正确重建 ACT 动作队列/TE 状态，才开始 ACT rollout。准备产生的事件不重复记到 ACT 名下。

传感器同步、速度估计、接触历史要连续有效；证据间隔超过现有 0.12 s 会撤销连续抓取认证。若改为保存/恢复快照，需要版本化物理状态和认证历史恢复接口；只恢复 q 与物体 pose 不够。

每个起点需记录 `start_valid`、实际观测、准备来源和 `assisted_initialization`。准备失败属于 `INIT_FAILED`，不统计成 ACT 失败或零奖励样本。准备阶段的仿真时间和墙钟时间单独计入训练成本。

## 4. 截止、失败和 PPO 边界

| 状态 | 截止行为 | PPO 语义 |
| --- | --- | --- |
| 阶段达标 | 独立段可结束采样；连接模式立即交给下一阶段评价，ACT 连续控制 | 阶段达标不等于完整任务 terminal；独立段结束采用采样边界并从末状态 bootstrap |
| 阶段预算用尽 | 记录 `TIMEOUT` 并重置/重新采样 | 若预算只服务采样效率，`truncated=True`；不伪装为完整任务失败 |
| 掉出工作区等真实任务失败 | 停止本条任务并保存失败原因 | `terminated=True`，不 bootstrap |
| 传感器无效、模拟崩溃、初始化失败 | 不继续声称拥有有效状态；按采集错误处理 | 不把未知数据构造成失败 transition；丢弃无效部分并另报采集质量 |

抓持丢失但物体仍可恢复时，记录局部失败里程碑，转回允许的抓取恢复，或结束当前采样段；它并不自动等价于整个任务不可恢复。回 HOME 时物体被打扰应记录 `completed_object_disturbed`，不能只看手臂姿态通过。

第一版建议采用“统一完整目标 + 阶段采样边界”。不要把 REACH 达标写成现有 `outcome=success`，也不能在中途套用完整成功奖金或清零原本需要 bootstrap 的终端势函数。完整目标真正完成时仍按相同奖励语义处理；辅助起点下完成剩余目标与从 HOME 自主完成，必须在指标中区别。

完整无辅助成功要求：从原始 HOME 起点开始、目标出现、全过程由 ACT 控制，且现有完整物理成功判据通过。`assisted_initialization=True` 的轨迹即使最后满足任务完成状态，也不能计入这个成功率。

如果以后改为真正独立的有限时域子任务，需单独设计阶段奖励、value 和终止契约，并给策略必要的目标/剩余时间信息；不能只在当前完整任务奖励上加几个 `done=True`。相关依据：[Time Limits in RL](https://proceedings.mlr.press/v80/pardo18a.html)。

## 5. 可见性与记录

终端/TensorBoard 至少展示：

```text
training_stage=GRASP_LIFT   physical_phase=grasp_lift
initialization=controller_reset   start_valid=true   assisted=true
elapsed=2.4/8.0s   grasp_valid=true   attempt_lifted=false
contact_hold=0.10s   lift_height=0.013m   stage_result=RUNNING
```

分离记录 `stage_success`、`stage_timeout`、`stage_failure_reason`、`task_goal_reached`、`full_unassisted_success`；保留场景 seed、阈值版本、起点证据、接管时间与阶段完成时间。HOME 报每轴误差/速度，REACH 报 XYZ/方向/开口，抓取报双指接触和相对漂移，后续报底面高度、goal membership、释放及稳定计时。日志用实际测量值，不用动作命令冒充执行结果。

## 6. 实施顺序和接口边界

第一批：`HOME_HOLD / REACH / GRASP_LIFT / FULL` 的阶段配置、合法起点、里程碑与采样边界。第二批：真实持物初始化验证后启用 `TRANSPORT / PLACE_RELEASE`；`RETURN_HOME` 可先通过辅助已完成场景练习，再加入真实释放衔接。

建议新增独立阶段配置/评估模块与初始化模块，通过 worker 的 `prepare_episode` 返回 `stage_start_certificate`；新增“准备后 ACT 接管”接口，不能用现有 `reset_from_feedback` 代替。主采样器维护各段时间预算、末状态 bootstrap、不同阶段的记录与 checkpoint 配置签名。原 task tracker 继续承担物理事实认证，原目标位置 curriculum 负责空间难度，二者不能混成同一个枚举。

课程调度先主攻精确 reach 与近物体抓取，同时保持 HOME；70/20/10 只是新采样步数比例候选。若近物体起点仍没有接触，应增加抓取采样并检查动作/几何，不能一直等待 reach 完美。后期提高无辅助完整流程比例，分别统计局部和整体成功率。

设计依据是通过有效初始状态逐渐扩展难度，而不是让机器人每次从同一起点等待偶然成功：[Reverse Curriculum](https://proceedings.mlr.press/v78/florensa17a.html)。上述抓放阈值主要来自本项目配置，新增条件和时间预算是项目设计建议，不是论文已验证参数。

## 7. 验证要求

实施后先验证每种起点能够重复准备且能被真实传感器正确认证；S3/S4 首帧不发放准备过程的事件奖金。用人工构造边界样本测试成功、超时、真实失败和无效数据的区分，再做真实 Gazebo 短段测试。单元测试无法证明可抓几何、持物稳定或全部碰撞都正确。

目前只有中心场景的受控抓取与约 3 cm 抬升得到单次 live 证据；搬运、放置起点尚未得到同等验证。配置当前仍为 `candidate_unvalidated`，不能把这份规格视为已完成的阶段训练系统。
